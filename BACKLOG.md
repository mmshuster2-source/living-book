# Living Book — журнал решений и бэклог

Обновлено: 2026-10-19. Рабочий журнал, не техническое задание. Статусы: **Принято**, **Сделать**, **Обсудить**, **Отложено**. Перенос в реализацию только по явному согласованию.

## Принято — принципы
- Авторский исходный текст и стиль сохраняются; смысловые блоки размечаются поверх непрерывной статьи.
- Блок имеет устойчивый ID, смысловое ядро и границы; примеры, аналогии и провокации допустимы, пока не создают самостоятельное ядро.
- Паспорт описывает положение и свойства блока во всей системе, отдельно от внутреннего текстового редактора.
- Статья: разметка и порядок блоков. Блок: текст, абзацы, внутренние операции. Паспорт справа.
- Абзац — адресуемый элемент с ID; замечания и связи должны переживать перестановку.
- «Изменить границы» доступно и при разметке статьи, и из блока; меняет принадлежность, но не текст или порядок.
- Болванка — незаполненный смысловой объект; размещение «ниже» (детализация) или «в повествовании» (на том же уровне); приоритет 1, 2, 3 или не назначен; только для автора.
- Читательская версия не содержит болванок и служебных атрибутов.
- Базовое повествование — порядок блоков в авторской статье; горизонтальные связи и альтернативные маршруты создаются по мере надобности, не «впрок».
- Режимы самостоятельности ИИ (монтаж авторских текстов, интерпретация без внешних источников, исследование с источниками) — концепция, экспериментировать позже.
- Автор может пересмотреть любое задание; предупреждать о рисках целостности данных, сопровождения и преждевременной сложности.

## Сделать — следующий короткий шаг
- [ ] Перенос **свободного абзаца в блок** без изменения ID, текста и привязок.
- [ ] Перенос **абзаца из блока в свободную область** без удаления текста.
- [ ] Дать для переноса понятное указание позиции, при этом сохранить простой первый интерфейс (начало/конец, перестановка внутри блока стрелками).
- [ ] Проверить сценарии с пустым блоком: ID и паспорт остаются, блок может быть болванкой; нынешняя реализация не во всех командах это поддерживает.
- [ ] Проверять результат сценариев в браузере до объявления готовности; одной проверки синтаксиса недостаточно.

## Сделать — эргономика и надёжность
- [ ] Не терять паспорта при исправлении разметки; команда «Убрать разметку» сохраняется с ясным предупреждением о последствиях.
- [ ] Компактный список операций в правой панели: Текст…, Перенести абзац…, Блок ↓, Блок →, Изменить границы, Убрать разметку.
- [ ] Сворачивание / разворачивание дерева и отдельных узлов; показ / скрытие болванок (переключатель уже есть).
- [ ] Правая панель-аккордеон, когда появится реальная потребность.
- [ ] Пересмотреть отсутствие истории изменений: резервный JSON сейчас остаётся важным.
- [ ] Улучшить сообщения об ограничениях операций: сообщать конкретную причину, избегать лишних подтверждений.
- [ ] Сохранение читательской публикации как отдельной фиксированной версии; не путать локальный предпросмотр и публичный URL.

## Обсудить — открытые вопросы
- [ ] Семантика полностью пустого блока и его превращение в болванку во всех операциях.
- [ ] Можно ли создавать новый блок из абзацев разных частей текста и как это согласуется с непрерывным повествованием.
- [ ] Правила изменения порядка блоков стрелками дерева, особенно если между ними есть свободные абзацы.
- [ ] Последствия удаления блока для его дочерних болванок и будущих связей: предупреждение сейчас, более мягкая операция позже.
- [ ] Нужно ли ограничивать редактирование текста по абзацам или позволять более свободную работу внутри блока при сохранении ID.
- [ ] Читательский счётчик открытий без регистрации: GitHub Pages не даёт встроенной аналитики, потребуется внешний сервис.
- [ ] Полномочия ИИ, атрибуция выводов, проверка логических переходов и источник каждого утверждения.

## Отложено — развитие системы знаний
- [ ] Типизированные горизонтальные связи и временные повествования, предлагаемые ИИ ситуационно.
- [ ] Семантический поиск по паспортам блоков, двухэтапное извлечение текста для больших корпусов.
- [ ] Служебные сценарии, обратная связь читателя, уровни его подготовки и траектории внимания.
- [ ] Иллюстрации, вычислительные макросы, запросы на данные; раздельные контракты интерпретации и исполнения.
- [ ] История изменений, происхождение вкладов, доверие и проверяемость утверждений.
- [ ] Предпубликационная ревизия как набор вкладов с отдельными решениями автора.
- [ ] Импорт старых материалов и создание цифрового двойника интеллектуального опыта.
- [ ] Счётчик посещений и эксперимент с публикацией в Facebook — только после готовности текста и читательского интерфейса.

## Состояние прототипа
- GitHub Pages редактор: `editor-v1-13.html`; последняя версия с выбором блока щелчком по абзацу.
- Редактор использует локальное хранилище браузера; экспорт/импорт JSON. Изменения не публикуются автоматически в читательской версии.
- Отдельная публичная статическая статья: `read-new-npp.html`, пока исходный текст.
- Последнее наблюдение: перенос между существующими блоками требует наличия второго блока; свободные абзацы не поддержаны.
- Полная очистка редактора убрана; «Убрать разметку» остаётся разрушительной для паспорта и дочерних болванок.
