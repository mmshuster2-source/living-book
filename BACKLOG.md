# Живая книга — решения и бэклог

Обновлено: 2026-10-20. Рабочий журнал, не техническое задание. Приоритеты **P0** — устойчивость/целостность, **P1** — ближайшая эргономика, **P2** — следующее развитие, **P3** — отложено. Статусы: **принято**, **сделать**, **исследовать**, **готово**.

**Принцип исполнения:** к текущей задаче можно попутно добавлять только независимую, обратимую работу без миграции данных и изменения смысловой модели; заранее сообщать о рисках. «Попутно» не означает самовольную реализацию всех пунктов.

## Принятые принципы
- **Статья — авторское произведение**, которое в процессе ревизии размечается в смысловые блоки. Старые статьи сначала сохраняются как произведения; не каждый фрагмент обязан стать существенным блоком.
- Состав: **книга / библиотека → статья → раздел → подраздел → блок → абзац**. Один блок находится в одном разделе/подразделе; подраздел содержит несколько блоков; свободные абзацы допустимы как черновое состояние.
- Абзацы и блоки имеют устойчивые ID. Перенос меняет принадлежность и место, не размножает текст, не обрывает замечания и не теряет паспорт. Нельзя делить блок переносом целого блока.
- Базовое повествование — авторская последовательность; смысловая детализация и горизонтальные связи — отдельные отношения, не обязанные повторять дерево состава.
- **Слева структура, в центре содержание, справа свойства и операции.** Больше представлений тех же объектов предпочтительнее создания лишних сущностей.
- Паспорт блока — авторское описание смыслового ядра, не механический пересказ абзацев. Паспорт статьи позднее позволит строить содержательное оглавление и многоступенчатый поиск.
- Публикуемый корпус имеет один актуальный экземпляр статьи/смыслового блока; исторические версии доступны по запросу, не навязываются читателю.
- Существенность изменения определяет **автор**. Существенное изменение требует отдельного авторского описания; косметическое не требует уведомления. Изменение может быть точкой входа в знания («провокацией»). Разные пояснения читателям не означают разные авторские версии сути изменения.
- ИИ может помогать анализировать и компоновать, но должен отличать авторский текст, интерпретацию ИИ и внешние источники. Реализация сквозного поиска — позднее.

## P0 — целостность и технический долг
- [ ] Регрессионные сценарии перед выпуском: создание блока и паспорта; выбор/перенос/освобождение абзаца; перенос целого блока между подразделами; создание/удаление пустого подраздела; проверка сохранения/импорта/экспорта. **Синтаксической проверки недостаточно**, браузерная проверка обязательна.
- [ ] Предупреждения о разрушительных действиях, особенно «Убрать разметку» (сейчас уничтожает паспорт и связанные болванки). Перед структурными миграциями — резервный JSON и тест восстановления.
- [ ] Улучшить ошибки операций (причина отказа вместо неопределённого сообщения); обработать пустые блоки и свободные абзацы, не теряя ID/замечаний.
- [ ] Проверить порядок и место свободных абзацев при перемещении блоков; обратимые действия предпочтительнее стирания.

## P1 — ближайшие небольшие улучшения интерфейса
- [ ] **Слои / редактор дерева**: выключатель редактирования, при выключении — чистое компактное дерево без кнопок и служебных значков. Только представление, данные не меняются.
- [ ] **Слои / признаки под абзацами**: вкл./выкл. служебного «обвеса» под абзацами. Начать с замечаний; будущие запросы, статусы, напоминания — P2, пока не вводить новые типы.
- [ ] **Заголовок / Название**: «Заголовок» — краткое имя узла в дереве; «Название» — полный заголовок в статье. Начальные значения совпадают, затем редактируются независимо. Уточнить правило для всех уровней, сохранив совместимость JSON.
- [ ] **Левая панель**: закрепить «Слои» внизу, дерево прокручивать независимо при недостатке места.
- [ ] **Правая панель**: убрать из видимого паспорта «Уровень абстракции», «Доверие / основания», «Теги» (НЕ удалять данные из JSON). Вернуть по отдельным задачам P3.
- [ ] **Разметка**: убрать пустую правую секцию-заглушку; внутриабзацные значки не реализовывать. Инструменты внимания должны жить под абзацем.
- [x] **Ревизия / фильтр**: в v1.30 добавлены чекбоксы «Отработанные», «Авторские», «Прочие»; фильтр скрывает, не удаляет. Значения не сохраняются между сеансами.
- [ ] **Ревизия / фильтр — развитие**: чекбоксы по всем имеющимся типам замечаний; не создавать новых сущностей. Подумать о сохранении фильтров между сеансами.
- [ ] **Правая панель — аккордеон**: панель операций «Содержание» (Текст…, перенос, освобождение, границы, разметка), отдельно свойства и замечания; сохранять раскрытие при переходе между сеансами. Ревизию пока оставить без аккордеона — фильтра достаточно.

## P1 — зрелость абзацев, фильтры и внимание читателя (2026-10-20)
- [ ] **Редакционный статус каждого абзаца:** «Скрытый», «Черновик», «В работе», «Публиковать». «Все» — режим фильтра, не статус. Приоритет — отдельный атрибут для скрытых/отложенных работ. Назначение статусов не должно менять текст, ID или принадлежность к блоку.
- [ ] **Панель «Слои» — редакция:** чекбоксы «Скрытые», «Черновик», «В работе», «Публиковать», «Приоритет», «Все». Определить интерпретацию комбинаций, дефолты и сохранение предпочтений. В читательской версии не раскрывать неопубликованные абзацы.
- [ ] **Панель «Слои» — замечания:** «ИИ», «Мои», «Действуют», «Приоритет», «Закрытые», «Все». Происхождение, жизненный цикл и приоритет — независимые оси фильтра. Согласовать с уже действующими фильтрами v1.30, не дублировать логику.
- [ ] **Панель «Слои» — элементы:** чекбоксы «Запросы» и «Комментарии». Сначала установить различие: что показывается читателю, что остаётся авторским, и как объекты привязываются к абзацам.
- [ ] **Читательский интерфейс:** статья + ненавязчивая нижняя панель элементов выбранного абзаца (комментарии, промпты/запросы). Продумать активацию: «Показать» по запросу и, отдельно, необязательный режим показа при перемещении курсора; исключить мелькание. Сначала прототип на текущих комментариях, без сложной персонализации.
- [ ] **Публикационная целостность:** определить вывод заголовка блока/подраздела при отсутствии опубликованных абзацев, а также сохранность якорей замечаний к скрытому тексту.
- [ ] **Свободное творчество (низкий риск, не срочно):** ввод отдельного нового текстового фрагмента, который после сохранения становится обычными свободными абзацами; не вмешиваться в ранее размеченные абзацы. Заголовки решать отдельно.
- [ ] **Авторский промпт / блок вопросов:** пока исследовать на реальных примерах как статус/содержимое обычных абзацев, без создания нового типа блока; разделить авторский вопрос и генерируемый ИИ ответ. До публикации решить, как не показывать служебные инструкции как готовое авторское утверждение.

## P2 — следующие представления и сценарии
- [ ] **Содержательное оглавление**: альтернативное представление дерева полными Названиями, возможно вместе с краткими содержаниями паспортов. Вначале переключаемый режим левой панели; регулируемая мышью граница — отдельно и только если потребуется.
- [ ] Разворачивание/сворачивание ветвей дерева и правила визуального отображения незавершённых структур.
- [ ] Расширение служебных значков и действий под абзацем: запрос, статус, напоминание, будущие обратные связи; отделить от текста и его ID.
- [ ] Редактирование текста и создание абзацев в центре статьи; перенести плюс добавления абзаца из дерева без потери возможности писать в пустом разделе.
- [ ] Паспорта статей; краткое содержательное представление статьи из паспортов её блоков.
- [ ] **Библиотека статей и каталог изданий**: независимое хранение каждой статьи, безопасная миграция нынешнего localStorage, переключение без перезаписи. Работа над произведением отделена от его опубликованного издания.
- [ ] Приведение позиции абзаца и блока в содержательном порядке, перемещение блоков внутри раздела с учётом свободных абзацев; отдельные правила для межстатейного переноса (пока запрещён).
- [ ] Архив редакций и авторские дайджесты **существенных** изменений. Читатель не обязан перечитывать изменённую статью; обновление — отдельный авторский смысловой объект. Пока исследование, не код.

## Исследовать до изменения модели (не брать попутно)
- [ ] **«Болванка» как статус блока вместо сущности**: сравнить поля, родительские связи, размещение «в тексте»/«ниже», приоритет и скрытие. Найти миграцию без потери паспортов и существующих болванок; подчистить код только после решения.
- [ ] Семантика пустого блока: статус, местоположение, возможность стать болванкой, последствия удаления для зависимых элементов.
- [ ] Одно понятие «название» в разных представлениях: что считается публичным, служебным, историческим; как редактируются связанные поля.
- [ ] Работа с абзацами из разных мест текста и последствия для непрерывной композиции.
- [ ] Границы ответственности читателя/автора за понимание обновлений; компетентность читателя по предметным областям и знакомство с авторским корпусом — независимые характеристики.

## P3 — отложенное развитие знаний и публикаций
- [ ] **Уровни абстракции**: содержательная модель и навигация по уровню детализации; поле пока скрыто.
- [ ] **Доверие и основания**: проверяемость утверждений, происхождение данных, авторская и внешняя экспертиза; поле пока скрыто.
- [ ] **Теги**: назначение, словарь и дисциплина использования; поле пока скрыто.
- [ ] Семантический поиск по паспортам статьи и блоков: индекс → подходящие блоки → полный текст; доступ из нового чата через инструмент, без загрузки всей библиотеки в контекст.
- [ ] Горизонтальные связи, повторное использование одного блока без дублирования, временные повествования.
- [ ] Режимы ответа ИИ: подбор авторских фрагментов; интерпретация на основании корпуса; внешнее исследование с источниками.
- [ ] Читательские траектории, реакции («прочёл», «вернуться», «не показывать»), персонализация по компетентности и прочитанному.
- [ ] Иллюстрации, вычислительные модели/макросы и контракты проверяемости и исполнения.
- [ ] Импорт старых работ, история развития авторской мысли и цифровой двойник интеллектуального опыта.
- [ ] Отдельная читательская публикация, последующие издания и аналитика просмотров (в т.ч. эксперимент Facebook), когда материал будет готов.

## Фактическое состояние на 2026-10-20
- Текущий редактор: **editor-v1-30.html**, GitHub Pages. JSON-импорт/экспорт, Markdown-экспорт; авторский/читательский предпросмотр.
- Есть разделы и одноуровневые подразделы, создание абзацев, выделение блоков с паспортом, перенос целых блоков в подразделы, перемещение абзацев между блоками (включая свободные), замечания автора/ИИ, фильтр ревизии.
- Черновик хранится локально в браузере под общим ключом **living-book-editor-v1**. Публикация в GitHub не обновляется автоматически; для перехода к библиотеке обязательны резервные копии и миграция.
- Публичная страница **read-new-npp.html** — отдельная фиксированная версия, не тождественна последнему локальному тексту.
- «Болванки» пока отдельная сущность; «Разметка» справа — неработающая заглушка. Поля абстракции, доверия, тегов пока видны, но предложены к скрытию.
- Экспортированный рабочий JSON пользователя после переносов проверялся: ошибок целостности структуры не обнаружено; это **не** содержательная экспертиза.
